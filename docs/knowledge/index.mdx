title: 知识系统
description: 了解 Locus 如何将会话、设计决策、长期记忆与可复用技能组织成面向 Unity 项目的知识系统。
---

知识系统是 Locus 让 Agent 持续理解 Unity 项目的方式。Agent 在会话、修改、调试过程中产生的判断与决策，会被沉淀到一个可被检索、可被审阅、可被复用的知识库中，而不是每次重新解释项目。

## 为什么 Unity 开发需要项目知识

Unity 项目的上下文不只是代码，还包括场景结构、资产约定、命名规范、构建流程，以及团队过去做过的决定。把这些信息留在 Agent 容易访问的位置，可以减少重复说明、降低误改风险，也让后续会话保持一致。

## 知识类别

Locus 当前将知识划分为以下几类：

- **Design**：项目的设计需求与事实基准。Agent 可在会话中提议更新（默认需要用户审批），用户也可手动维护。
- **Memory**：由 Agent 维护的动态上下文，例如用户偏好、历史问题与项目理解。
- **Skill**：标准化的工作流程。可以用自然语言描述一次，让 Agent 在遇到同类场景时按这个 Skill 执行。
- **Reference**：外部只读资料，例如 Unity API 文档或团队已有的文档库。

## 知识如何沉淀

知识不需要一次写完，它通常来自日常使用：

- 会话中得到澄清的需求会更新到 Design
- 用户偏好与重复出现的项目特征会进入 Memory
- 反复执行的流程会被固化为 Skill
- 已有的外部资料可以作为 Reference 接入

## 当前阶段

Locus 仍处于 v0.2.3 早期测试阶段，知识系统的能力还在持续演进。现阶段建议把它当作可以辅助 Agent 工作的项目上下文层来使用，并在重要修改前保留人工审阅。
